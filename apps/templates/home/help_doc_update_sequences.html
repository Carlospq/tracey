What it does — For every TRACEY sequence that was originally imported from NCBI (i.e. it stores an NCBI ID), TRACEY re-fetches the current record from NCBI (esummary/efetch) and compares it against what is stored locally. Depending on what changed, it will:

  • Update the accession (dbxref) if NCBI issued a new version.
  • Update the sequence status (live, replaced NCBI, suppressed, dead, crystal structure, ignore, ...) to match NCBI.
  • Follow "replaced by" chains on NCBI and create the new replacement entry in TRACEY if it doesn't exist yet.
  • Re-scan for motifs (HMM domains) on sequences that are now live but don't have any yet.
  • Refresh the shortname and gene aliases when missing.

'Live' sequences without an NCBI Id are manually curated entries and are never touched by this feature.


All species / Shortname — By default the update runs against every eligible sequence in TRACEY ("All species"). Choosing "Shortname" restricts the run to a single taxon: type at least 2 characters in the box to search TRACEY taxonomies by shortname or scientific name, then click a suggestion to fill it in (e.g. HoSa for Homo sapiens). If the selected taxon is a strain, varietas, or has no formal rank, its parent species is included automatically. See the shortname help for the naming convention.


Protein family — Limits the update to sequences that already carry a motif for that family in TRACEY (e.g. only sequences with a SNARE or Habc motif when "SNARE" is selected). This keeps the run focused and avoids querying NCBI for unrelated sequences.


Duration — This queries NCBI once per sequence (and again for every near-identical sequence it finds in the same species, to decide which one stays "live"), so a full run can take from minutes to several hours depending on how many sequences match the filters. It runs in the background: you can navigate away and check progress and the full report later via "Check last update results".
